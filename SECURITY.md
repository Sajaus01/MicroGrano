# Comunicación de problemas de seguridad

No publique credenciales, datos personales, imágenes privadas ni instrucciones que permitan explotar una vulnerabilidad en una incidencia pública. Las sesiones y los registros pueden contener datos importados, rutas locales y otros detalles del entorno; revíselos antes de compartirlos.

Si GitHub muestra la opción **Report a vulnerability** en la sección **Security** del repositorio, utilice ese canal privado. La presencia de este archivo no implica que la opción esté habilitada. Si no está disponible, abra una [incidencia](https://github.com/Sajaus01/MicroGrano/issues) que indique únicamente que necesita comunicar un problema de seguridad y solicite un canal privado antes de enviar los detalles. No se publica aquí una dirección de contacto distinta de los canales del repositorio.

En la comunicación privada, indique la versión afectada, el entorno, el comportamiento observado y los pasos mínimos de reproducción con datos sintéticos. Diferencie el impacto comprobado del que considere posible. Este documento no establece un plazo de respuesta ni garantiza soporte para una versión determinada.

Los errores de funcionamiento que no expongan un problema de seguridad pueden comunicarse según [CONTRIBUTING.md](CONTRIBUTING.md).
